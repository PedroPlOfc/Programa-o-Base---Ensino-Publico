## 1. Branches — Desenvolvimento Paralelo

### O que é uma Branch?

Uma branch é uma **linha independente de desenvolvimento**. Imagine o projeto como uma estrada: a branch `main` é a rodovia principal (código estável, em produção). Branches de feature são **desvios temporários** onde você constrói algo novo sem afetar a estrada principal.

```
main ──────────●──────────────────────────●────── (produção)
               │                          ↑
               └── feature/login ──●──●───┘ (merge)
                        └── hotfix/bug ─●─►  (branch de urgência)
```

### Por que usar branches?

- ✅ Isola o desenvolvimento — código incompleto não entra na `main`
- ✅ Múltiplos devs trabalham em paralelo sem se atrapalhar
- ✅ Facilita Code Review (Pull Requests)
- ✅ Permite reverter uma feature inteira se necessário

### Comandos Essenciais de Branch

```bash
# Listar todas as branches locais
git branch

# Listar branches remotas também
git branch -a

# Criar uma nova branch (sem mudar para ela)
git branch feature/pagina-contato

# Criar e já mudar para a nova branch (forma mais usada)
git checkout -b feature/pagina-contato

# Versão moderna (Git 2.23+) — preferida
git switch -c feature/pagina-contato

# Navegar para uma branch existente
git checkout main
git switch main          # versão moderna

# Renomear a branch atual
git branch -m novo-nome

# Deletar uma branch (após o merge)
git branch -d feature/pagina-contato    # seguro: avisa se não fez merge
git branch -D feature/pagina-contato    # força a deleção mesmo sem merge

# Deletar branch remota
git push origin --delete feature/pagina-contato
```

### Estratégia de Nomenclatura (padrão de mercado)

```
feature/nome-da-funcionalidade    → nova feature
fix/descricao-do-bug              → correção de bug
hotfix/bug-critico                → correção urgente na produção
release/v1.2.0                    → preparação de release
docs/atualiza-readme              → apenas documentação
refactor/separa-componentes       → refatoração sem nova feature
```

### Fluxo Completo com Branch

```bash
# 1. Sempre parta de uma main atualizada
git switch main
git pull origin main

# 2. Crie sua branch de trabalho
git switch -c feature/sistema-de-pagamento

# 3. Trabalhe normalmente: edite, add, commit
git add .
git commit -m "feat: adiciona integração com Stripe"
git commit -m "feat: adiciona tela de confirmação de pagamento"
git commit -m "test: adiciona testes do fluxo de pagamento"

# 4. Suba sua branch para o GitHub
git push -u origin feature/sistema-de-pagamento

# 5. Abra um Pull Request no GitHub para revisão
# (feito pela interface web do GitHub)

# 6. Após aprovação e merge no GitHub, limpe localmente
git switch main
git pull origin main
git branch -d feature/sistema-de-pagamento
```

## 2. Merge e Rebase — Unindo o Trabalho

### Git Merge

O `merge` une duas branches **preservando o histórico completo**, incluindo quando a branch foi criada e os commits individuais.

```bash
# Estando na branch de destino (geralmente main):
git switch main
git merge feature/pagina-contato

# Merge com mensagem customizada
git merge feature/pagina-contato -m "merge: integra página de contato"

# Merge sem criar commit de merge automático (fast-forward)
git merge feature/pagina-contato --ff-only
```

**Tipos de merge:**

```
Fast-Forward (branch linear, sem commits novos na main):
main: A ── B
                └── C ── D  (feature)
resultado: A ── B ── C ── D  (main avança)

Merge Commit (main teve novos commits enquanto você trabalhava):
main: A ── B ────── E
              └── C ── D  (feature)
resultado: A ── B ── E ── M  (M = commit de merge)
                └── C ── D ──┘
```

### Git Rebase

O `rebase` **reescreve o histórico**, movendo seus commits para o topo da branch de destino. Resulta em um histórico mais linear e limpo.

```bash
# Estando na sua feature branch:
git switch feature/pagina-contato
git rebase main

# Rebase interativo — permite editar, juntar e reordenar commits
git rebase -i HEAD~3    # abre os últimos 3 commits para editar
```

**Exemplo de rebase interativo:**
```
pick a1b2c3 feat: adiciona estrutura HTML da página
pick d4e5f6 fix: corrige typo
pick g7h8i9 feat: adiciona CSS da página

# Você pode mudar para:
pick a1b2c3 feat: adiciona estrutura HTML da página
squash d4e5f6 fix: corrige typo       ← junta com o commit anterior
pick g7h8i9 feat: adiciona CSS da página
```

> ⚠️ **Regra de ouro do Rebase:** Nunca faça rebase em branches compartilhadas (`main`, `develop`). Só use em **suas branches locais** antes de dar push.

### Merge vs Rebase — Quando usar?

| Situação                              | Use            |
|---------------------------------------|----------------|
| Feature pronta indo para main         | `merge`        |
| Atualizar sua branch com a main       | `rebase`       |
| Quero histórico linear e limpo        | `rebase`       |
| Quero preservar contexto temporal     | `merge`        |
| Branch já está no remoto/compartilhada| `merge`        |

## 3. Resolvendo Conflitos

Conflitos acontecem quando **duas pessoas editam o mesmo trecho** do mesmo arquivo em branches diferentes. Não é erro — é parte normal do trabalho em equipe.

### Como Conflitos Aparecem

```bash
git merge feature/cabecalho
# Auto-merging src/App.js
# CONFLICT (content): Merge conflict in src/App.js
# Automatic merge failed; fix conflicts and then commit the result.
```

### Estrutura de um Conflito

Quando você abre o arquivo conflitado, verá marcadores assim:

```javascript
<<<<<<< HEAD
// Seu código (branch atual)
const titulo = "Minha Loja";
=======
// Código que está chegando (branch que você quer fazer merge)
const titulo = "Loja Online Premium";
>>>>>>> feature/cabecalho
```

### Como Resolver

**Opção 1 — Manualmente no VS Code:**
O VS Code exibe botões acima do conflito:
- `Accept Current Change` → fica com o seu código
- `Accept Incoming Change` → fica com o código da outra branch
- `Accept Both Changes` → mantém os dois
- `Compare Changes` → vê o diff lado a lado

**Opção 2 — Manualmente no terminal:**
1. Abra o arquivo
2. Escolha qual versão manter (ou combine as duas)
3. Delete os marcadores `<<<<<<<`, `=======`, `>>>>>>>`
4. Salve o arquivo

**Após resolver:**
```bash
# Marque o conflito como resolvido
git add src/App.js

# Continue o merge
git commit -m "merge: resolve conflito no título da loja"
```

### Abortando o Merge (se quiser desistir)

```bash
git merge --abort       # Volta ao estado antes do merge
git rebase --abort      # Volta ao estado antes do rebase
```

## 4. Operações de Resgate

### Desfazendo Mudanças no Working Tree (antes do stage)

```bash
# Descarta alterações de UM arquivo (volta para o último commit)
git restore index.html

# Descarta alterações de TODOS os arquivos
git restore .

# ⚠️ Cuidado: essas alterações são perdidas permanentemente
```

### Desfazendo o Stage (saindo do git add)

```bash
# Remove um arquivo do stage (mas mantém as alterações no código)
git restore --staged index.html

# Remove tudo do stage
git restore --staged .
```

### Desfazendo Commits com `git reset`

```bash
# --soft: desfaz o commit, mantém arquivos no stage
# (como se você nunca tivesse dado commit, mas ainda está no git add)
git reset --soft HEAD~1

# --mixed (padrão): desfaz o commit, remove do stage, mantém código
git reset HEAD~1
git reset --mixed HEAD~1

# --hard: desfaz o commit E descarta todas as mudanças do código
# ⚠️ PERIGO: mudanças são perdidas permanentemente
git reset --hard HEAD~1

# Volta para um commit específico pelo hash
git reset --soft a3f1c2d
```

> 💡 `HEAD~1` significa "1 commit antes do HEAD". `HEAD~3` significa "3 commits atrás".

### Desfazendo com `git revert` (mais seguro para equipes)

O `revert` cria um **novo commit que desfaz** as mudanças de um commit anterior. Diferente do `reset`, ele **não reescreve o histórico** — é o jeito correto de desfazer em branches compartilhadas.

```bash
# Desfaz o último commit criando um novo commit inverso
git revert HEAD

# Desfaz um commit específico
git revert a3f1c2d

# Revert sem abrir o editor de mensagem
git revert HEAD --no-edit
```

### Recuperando com `git stash`

O `stash` é como uma **gaveta temporária**: guarda suas mudanças não commitadas para você trocar de branch sem perder o trabalho.

```bash
# Guarda todas as mudanças na gaveta
git stash

# Guarda com um nome descritivo
git stash save "WIP: formulário de contato incompleto"

# Lista o que está na gaveta
git stash list
# stash@{0}: WIP on main: formulário de contato incompleto
# stash@{1}: WIP on feature/login: adiciona validação

# Recupera o stash mais recente (e remove da gaveta)
git stash pop

# Recupera um stash específico
git stash pop stash@{1}

# Aplica sem remover da gaveta (útil para aplicar em múltiplas branches)
git stash apply stash@{0}

# Descarta o stash mais recente
git stash drop

# Descarta todos os stashes
git stash clear
```

**Cenário real:**
```bash
# Você está trabalhando na feature/login e precisa urgente corrigir um bug na main
git stash save "WIP: validação de email ainda incompleta"
git switch main
git switch -c hotfix/crash-na-pagina-inicial
# ... corrige o bug, commit, merge ...
git switch feature/login
git stash pop     # recupera exatamente onde parou
```

## 5. Trabalhando com o Histórico

### `git log` — Explorador do Histórico

```bash
# Histórico completo (modo padrão)
git log

# Compacto — uma linha por commit
git log --oneline

# Com gráfico de branches
git log --oneline --graph --all

# Últimos N commits
git log -n 5 --oneline

# Commits de um autor específico
git log --author="Nome do Dev" --oneline

# Commits num intervalo de datas
git log --after="2024-01-01" --before="2024-06-30" --oneline

# Commits que modificaram um arquivo específico
git log --follow -- src/App.js

# Mostra as mudanças de cada commit (patch)
git log -p
```

**Exemplo de saída do `git log --oneline --graph --all`:**
```
* a3f1c2d (HEAD -> main, origin/main) feat: adiciona dashboard
* b9e4d1a fix: corrige erro no login
| * c2a7f3b (feature/relatorios) feat: adiciona relatório mensal
|/
* d1b5e8c feat: implementa autenticação JWT
* e4f2a1c docs: atualiza README
```

### `git diff` — Comparando Versões

```bash
# Diferenças não staged (o que você mudou mas não fez add)
git diff

# Diferenças que estão no stage (o que vai no próximo commit)
git diff --staged

# Diferenças entre dois commits
git diff a3f1c2d b9e4d1a

# Diferenças entre duas branches
git diff main feature/login

# Diferenças de um arquivo específico
git diff HEAD -- src/App.js
```

### `git show` — Inspecionando um Commit

```bash
# Mostra detalhes do último commit
git show

# Mostra detalhes de um commit específico
git show a3f1c2d

# Mostra apenas os arquivos modificados num commit
git show a3f1c2d --name-only

# Mostra o conteúdo de um arquivo em um commit específico
git show a3f1c2d:src/App.js
```

### `git blame` — Quem Escreveu Essa Linha?

```bash
# Mostra autor e commit de cada linha do arquivo
git blame src/App.js

# Com data
git blame -w --date=short src/App.js
```

Saída:
```
a3f1c2d (João Silva  2024-03-15) const App = () => {
b9e4d1a (Maria Costa 2024-03-18)   return <Dashboard />;
```

## 6. Comandos para Trabalho em Equipe

### Clonando um Repositório

```bash
# Clona o repositório completo com todo o histórico
git clone https://github.com/usuario/repositorio.git

# Clona para uma pasta com nome diferente
git clone https://github.com/usuario/repositorio.git meu-projeto

# Clona apenas a branch específica (mais rápido para repos grandes)
git clone --branch feature/login --single-branch https://github.com/usuario/repo.git

# Clona sem histórico (só o estado atual — útil para deploy)
git clone --depth 1 https://github.com/usuario/repositorio.git
```

### Sincronizando com o Remoto

```bash
# Baixa E integra mudanças do remoto (fetch + merge)
git pull

# Versão explícita
git pull origin main

# Pull com rebase (evita commits de merge desnecessários)
git pull --rebase origin main

# Baixa mudanças SEM integrar (para revisar antes)
git fetch origin

# Após o fetch, você pode ver o que chegou:
git log HEAD..origin/main --oneline    # commits novos no remoto
git diff HEAD origin/main              # diferenças
git merge origin/main                  # aí integra quando quiser
```

### Gerenciando Remotos

```bash
# Lista os remotos configurados
git remote -v

# Adiciona um novo remoto
git remote add origin https://github.com/usuario/repo.git
git remote add upstream https://github.com/projeto-original/repo.git

# Muda a URL de um remoto
git remote set-url origin https://github.com/usuario/novo-repo.git

# Remove um remoto
git remote remove upstream

# Renomeia um remoto
git remote rename origin github
```

### Tags — Marcando Versões

Tags são como **commits nomeados** — usadas para marcar versões de release.

```bash
# Cria uma tag leve
git tag v1.0.0

# Cria uma tag anotada (recomendada — tem metadados)
git tag -a v1.0.0 -m "Release versão 1.0.0 — MVP lançado"

# Lista todas as tags
git tag

# Envia a tag para o GitHub
git push origin v1.0.0

# Envia todas as tags de uma vez
git push origin --tags

# Verifica detalhes de uma tag
git show v1.0.0

# Deletar tag local
git tag -d v1.0.0

# Deletar tag remota
git push origin --delete v1.0.0
```

## 7. Commits Semânticos — Padrão de Mercado

### O Padrão Conventional Commits

O [Conventional Commits](https://www.conventionalcommits.org) é um padrão adotado por grandes empresas (Google, Microsoft, Angular, Vue.js) e projetos open-source. Ele torna o histórico **legível por humanos e por ferramentas** de automação.

### Estrutura Completa

```
<tipo>(<escopo>): <descrição>
<linha em branco>
<corpo>
<linha em branco>
<rodapé>
```

**Exemplo completo:**
```
feat(auth): implementa autenticação via OAuth 2.0

Adiciona suporte a login com Google e GitHub.
O token JWT agora tem validade configurável via env.

BREAKING CHANGE: o campo 'user_id' foi renomeado para 'userId'
Closes #123
Refs #456
```

### Tabela Completa de Tipos

| Tipo       | Propósito                                           | Gera versão? |
|------------|-----------------------------------------------------|--------------|
| `feat`     | Nova funcionalidade para o usuário final            | Minor ↑      |
| `fix`      | Correção de bug que afeta o usuário                 | Patch ↑      |
| `docs`     | Documentação apenas (README, JSDoc, guias)          | Não          |
| `style`    | Formatação, ponto e vírgula, espaços — sem lógica   | Não          |
| `refactor` | Refatoração de código sem mudar comportamento       | Não          |
| `test`     | Adiciona ou corrige testes                          | Não          |
| `chore`    | Build, dependências, configurações gerais           | Não          |
| `perf`     | Melhoria de performance                             | Patch ↑      |
| `ci`       | Mudanças em arquivos de CI/CD                       | Não          |
| `build`    | Sistema de build, compiladores, ferramentas externas| Não          |
| `revert`   | Reverte um commit anterior                          | Patch ↑      |
| `BREAKING` | Mudança que quebra compatibilidade retroativa       | Major ↑      |

### Exemplos Práticos por Tipo

```bash
# feat — Nova funcionalidade
git commit -m "feat: adiciona busca por filtro de categoria"
git commit -m "feat(cart): implementa cálculo de frete com correios API"
git commit -m "feat(user)!: migra autenticação para OAuth"  # ! = breaking change

# fix — Correção de bug
git commit -m "fix: corrige crash ao tentar fazer login offline"
git commit -m "fix(api): corrige timeout nas requisições de upload"
git commit -m "fix(mobile): corrige teclado sobrepondo formulário no iOS"

# docs — Documentação
git commit -m "docs: adiciona guia de contribuição ao projeto"
git commit -m "docs(api): atualiza documentação do endpoint /users"

# refactor — Refatoração
git commit -m "refactor: extrai lógica de validação para módulo separado"
git commit -m "refactor(auth): simplifica fluxo de refresh de token"

# test — Testes
git commit -m "test: adiciona cobertura de testes ao módulo de pagamento"
git commit -m "test(login): adiciona cenários de erro de autenticação"

# chore — Manutenção
git commit -m "chore: atualiza dependências do package.json"
git commit -m "chore(ci): adiciona lint check no pipeline de PR"

# perf — Performance
git commit -m "perf: substitui loop por operação de array vetorizada"
git commit -m "perf(db): adiciona índice na coluna user_id da tabela orders"
```

### Breaking Changes

Uma breaking change é uma mudança que **quebra compatibilidade** com versões anteriores (ex: renomear uma API, remover um campo).

```bash
# Opção 1: exclamação no tipo
git commit -m "feat(api)!: renomeia endpoint /user para /users"

# Opção 2: no rodapé do commit
git commit -m "refactor(auth): migra para novo sistema de tokens

BREAKING CHANGE: o token agora expira em 1h ao invés de 24h.
Clientes precisam implementar refresh automático."
```

### Ferramentas que Usam Commits Semânticos

- **semantic-release** → gera versões automaticamente baseado nos commits
- **conventional-changelog** → gera CHANGELOG.md automaticamente
- **commitlint** → valida que seus commits seguem o padrão
- **Renovate / Dependabot** → usa para categorizar updates

## 8. Cheat Sheet Final

### Configuração
```bash
git config --global user.name "Nome"
git config --global user.email "email@email.com"
git config --global init.defaultBranch main
git config --global --list
```

### Repositório
```bash
git init                              # Inicia repo local
git clone <url>                       # Clona repo remoto
git remote add origin <url>           # Conecta ao GitHub
git remote -v                         # Lista remotos
```

### Dia a Dia
```bash
git status                            # Estado dos arquivos
git diff                              # Diferenças não staged
git diff --staged                     # Diferenças no stage
git add .                             # Stage tudo
git add <arquivo>                     # Stage específico
git add -p <arquivo>                  # Stage interativo (por trecho)
git commit -m "tipo: mensagem"        # Cria checkpoint
git push                              # Envia ao remoto
git pull                              # Baixa e integra do remoto
git fetch                             # Baixa sem integrar
```

### Branches
```bash
git branch                            # Lista branches locais
git branch -a                         # Lista todas (local + remota)
git switch -c feature/nome            # Cria e muda de branch
git switch main                       # Muda para branch existente
git merge feature/nome                # Faz merge
git branch -d feature/nome            # Deleta branch (seguro)
git branch -D feature/nome            # Força deleção
```

### Resgate
```bash
git restore <arquivo>                 # Desfaz mudanças não staged
git restore --staged <arquivo>        # Remove do stage
git stash                             # Guarda mudanças temporariamente
git stash pop                         # Recupera do stash
git reset --soft HEAD~1               # Desfaz commit, mantém stage
git reset HEAD~1                      # Desfaz commit, remove stage
git reset --hard HEAD~1               # Desfaz commit e código ⚠️
git revert HEAD                       # Cria commit inverso (seguro)
```

### Histórico
```bash
git log --oneline --graph --all       # Histórico visual
git log -n 5 --oneline                # Últimos 5 commits
git log --author="Nome"               # Por autor
git show <hash>                       # Detalhes de um commit
git blame <arquivo>                   # Autor de cada linha
git diff main feature/nome            # Diferença entre branches
```

### Tags
```bash
git tag -a v1.0.0 -m "Release v1.0.0" # Cria tag anotada
git tag                                # Lista tags
git push origin v1.0.0                 # Envia tag
git push origin --tags                 # Envia todas as tags
```
